# 本地运行指南

> 目标：让任何人在一台干净的机器上，从克隆到打开系统不超过 15 分钟。
> 本文分两部分：**第一部分给技术人员**（照步骤执行）；**第二部分是一段提示词**（直接发给任意 AI 编码助手，让它替你把系统跑起来）。

- 演示地址：`http://localhost:5173`
- 演示账号：`admin` / `Admin@123`（管理员，全部功能）；`T2026002` / `Admin@123`（PI 项目负责人，受限菜单）
- 后端健康检查：`http://localhost:8080/actuator/health`

---

## 第一部分 · 技术人员操作手册

### 0. 环境要求

| 组件 | 版本 | 用途 |
|---|---|---|
| JDK | 21+ | 后端构建与运行 |
| Node.js | 20+（建议 22/24） | 前端构建与开发服务器 |
| Docker | 任意近期版本 | 拉起 PostgreSQL 16 / Redis 7 / MinIO |
| Maven | 不需要 | 仓库自带 `mvnw` wrapper |

> 后端测试另会下载嵌入式 PostgreSQL（Zonky）二进制，无需本地安装；若无法运行 Docker，见 [附录 A](#附录-a-无-docker-的替代方案)。

### 1. 拉起基础设施（一次性）

```bash
git clone <本仓库地址> rpm && cd rpm
docker compose up -d          # PostgreSQL 16 + Redis 7 + MinIO（自动创建 rpm-files 桶）
docker compose ps             # 等待三个服务均 healthy
```

默认端口与凭据（与 `backend/src/main/resources/application-dev.yml` 对齐，均可不配任何环境变量直接启动）：

| 服务 | 端口 | 凭据 |
|---|---|---|
| PostgreSQL | 5432 | 库 `rpm` / 用户 `rpm` / 密码 `rpm` |
| Redis | 6379 | 无密码 |
| MinIO | 9000（API）/ 9001（控制台） | `minioadmin` / `minioadmin` |

### 2. 启动后端

```bash
cd backend
./mvnw spring-boot:run        # Windows 用 mvnw.cmd；首次构建约 3~5 分钟
```

启动过程会自动完成：
1. Flyway 执行 13 个迁移（建表 + Flowable 独立 schema + 初始化 48 个权限码 + 管理员账号）；
2. 部署开发用审批流程定义；
3. 启动审计 Outbox 补写与物化视图刷新的后台任务。

看到如下日志即启动成功：

```
Started RpmApplication in xx.xxx seconds
```

验证：`curl http://localhost:8080/actuator/health` → `{"status":"UP"}`

### 3. 启动前端

```bash
cd frontend
npm install                   # 首次约 1 分钟
npm run dev                   # 开发服务器，已配置 /api → localhost:8080 代理
```

### 4. 初始化演示数据（可选但推荐）

空库只有管理员账号。执行演示种子数据可获得组织、人员、项目、申报、审批流、预算/支出、对账批次等完整演示场景：

```bash
docker exec -i rpm-postgres psql -U rpm -d rpm < demo/seed.sql
```

> seed.sql 是幂等的（`ON CONFLICT DO NOTHING`），可重复执行。
> `demo/objects/` 内含两个样例文件（交付物/周期报告），供演示上传对照。

### 5. 冒烟验证清单

登录 `admin / Admin@123` 后按此路径走一遍核心闭环：

| 步骤 | 页面 | 验证点 |
|---|---|---|
| 1 | 工作台 | 四项统计有数（已导入种子数据时） |
| 2 | 申报管理 → 新建申报 | 动态表单按模板渲染；保存草稿→提交进入审批 |
| 3 | 审批中心 → 待办事项 | 出现刚提交的申报；点「处理」→ 通过/退回/拒绝 |
| 4 | 审批中心 → 我发起的 / 已办事项 | 实例状态与轨迹 |
| 5 | 经费管理 → 预算/支出 | 预算版本、支出创建与提交 |
| 6 | 换 `T2026002` 登录 | 侧边栏**没有**「对账管理」（角色菜单过滤生效） |

命令行冒烟（无需浏览器）：

```bash
# 登录换取 token
TOKEN=$(curl -s -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"employeeNo":"admin","password":"Admin@123"}' | sed -n 's/.*"accessToken":"\([^"]*\)".*/\1/p')

# 带链路追踪头调用业务接口（响应头会回传同一 X-Trace-Id）
curl -s "http://localhost:8080/api/v1/applications?page=1&size=5" \
  -H "Authorization: Bearer $TOKEN" -H "X-Trace-Id: my-first-trace"
```

### 6. 运行测试

```bash
# 后端：1068 个测试（单测 + 嵌入式 PG16 集成 + Flowable 集成 + 行级权限 SQL 集成）
cd backend && ./mvnw test

# 前端：类型检查 + 生产构建（vue-tsc 零错误是提交门槛）
cd frontend && npm run build
```

### 7. 停止与清理

```bash
docker compose down          # 停止（保留数据卷）
docker compose down -v       # 停止并清空数据（下次启动重新迁移+导入种子）
```

### 附录 A：无 Docker 的替代方案

| 服务 | 替代做法 |
|---|---|
| PostgreSQL | 本地安装 PG 16，建库与账号：`CREATE USER rpm WITH PASSWORD 'rpm'; CREATE DATABASE rpm OWNER rpm;` |
| Redis | 本地安装 Redis 7；**Redis 不可用时系统仍可运行**（权限缓存自动降级回源数据库，仅性能受影响） |
| MinIO | 本地安装 MinIO 并手动建桶 `rpm-files`；启动后端时设置 `MINIO_ACCESS_KEY`/`MINIO_SECRET_KEY` 环境变量（dev 默认 `minioadmin/minioadmin`） |

### 附录 B：常见问题

| 现象 | 原因与处理 |
|---|---|
| 后端启动报 `Connection refused: localhost:5432` | PostgreSQL 未就绪；`docker compose ps` 确认 healthy 后重试 |
| 登录 401 | 确认密码 `Admin@123`；若执行过 `docker compose down -v`，管理员由 Flyway 重建，密码不变 |
| 上传文件 4xx | MinIO 桶缺失；重新 `docker compose up -d`（minio-init 会补建 `rpm-files`） |
| 前端页面空白 | 确认后端 8080 已启动（vite 代理指向 8080）；F12 Network 查看 `/api` 请求 |
| 端口冲突 | `SERVER_PORT`（后端）与 `vite.config.ts` 中 `server.port`（前端）可改 |

## 第二部分 · AI 一键运行提示词

> 把下面整段复制给任意具备终端执行能力的 AI 编码助手（Claude Code / Codex / Cursor 等），
> 在本仓库根目录的会话中发送即可。它描述了目标、环境、步骤与验收标准，AI 可独立完成并自查。

```markdown
请在这台机器上把「科研项目全生命周期管理系统」完整跑起来并向我汇报结果。仓库就在当前目录。

【系统构成】
- backend/  ：Java 21 + Spring Boot 3.5 多模块 Maven 工程（自带 mvnw wrapper），端口 8080
- frontend/ ：Vue 3 + Vite + TypeScript，端口 5173，开发代理 /api → localhost:8080
- 依赖服务 ：PostgreSQL 16（库 rpm/用户 rpm/密码 rpm，端口 5432）、Redis 7（端口 6379）、
             MinIO（端口 9000，桶 rpm-files，凭据 minioadmin/minioadmin）
- 仓库根的 docker-compose.yml 可一键拉起全部依赖（含自动建桶的 minio-init 服务）

【你要执行的步骤】
1. 检查环境：java -version（需 21+）、node -v（需 20+）、docker --version；缺少则先告诉我缺什么，能装的用本机包管理器安装。
2. 在仓库根执行 `docker compose up -d`，用 `docker compose ps` 确认 postgres/redis/minio 三个服务都 healthy（MinIO 桶由 minio-init 自动创建）。
   - 如果本机无法使用 Docker：改为本地安装 PostgreSQL 16 并执行
     `CREATE USER rpm WITH PASSWORD 'rpm'; CREATE DATABASE rpm OWNER rpm;`，
     再安装 Redis 与 MinIO（手动创建桶 rpm-files），然后继续。
3. 启动后端：进入 backend/ 目录，用仓库自带 wrapper 构建，命令
   `./mvnw spring-boot:run`（Windows 下用 `mvnw.cmd`；JAVA_HOME 指向 JDK 21）。
   Flyway 会自动执行 13 个迁移并初始化权限与管理员账号。等待日志出现 `Started RpmApplication`。
4. 用 curl 验证后端：`curl http://localhost:8080/actuator/health` 应返回 {"status":"UP"}。
5. 启动前端：进入 frontend/ 目录，`npm install` 后 `npm run dev`。
6. 导入演示数据：`docker exec -i rpm-postgres psql -U rpm -d rpm < demo/seed.sql`（幂等，可重复执行；
   无 Docker 时改用本地 psql 执行同一文件）。
7. 冒烟验证（必须全部完成才算成功）：
   a. POST http://localhost:8080/api/v1/auth/login，body {"employeeNo":"admin","password":"Admin@123"}，
      应返回 accessToken；
   b. 用该 token 调 GET /api/v1/applications?page=1&size=5（头 Authorization: Bearer <token>），
      应返回 code=OK 与分页数据；再带一个自定义请求头 X-Trace-Id: ai-smoke-001，
      确认响应头回传了相同的 X-Trace-Id；
   c. 用 refreshToken（登录响应里的另一个 token）冒充 accessToken 调上一步接口，应返回 401
      （双 token 类型隔离是本系统的安全设计）；
   d. GET /api/v1/workflow/instances/initiated?page=1&size=5 用正常 accessToken 调用，应返回 code=OK。
8. 打开 http://localhost:5173 确认登录页可访问（如你无法操作浏览器，告诉我手动验证的入口即可）。

【汇报要求】
- 每一步的执行结果（成功/失败与关键输出摘要）；
- 最终汇报：前端地址、演示账号（admin / Admin@123，PI 角色演示账号 T2026002 / Admin@123）、
  后端健康检查结果、冒烟验证 a~d 的实际返回；
- 任何一步失败：贴出错误日志、分析原因、修复后重试，不要跳过。
```
