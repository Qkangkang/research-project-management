## 2. 本轮（2026-11-17）需求评审拍板详述

### 2.1 D-13 特批采用禁止负余额模型

- **结论：**预算不足默认阻止提交；特批＝有独立权限的快速预算调整/支出审批通道，**任何时点可用余额 ≥ 0**。
- **否决的备选：**①允许特批负余额——破坏可用余额公式、报表与对账口径一致性，且需返工技术设计（05 文档余额公式、物化视图）；②一期不做特批——业务可能卡单。
- **影响回写：**PRD §0.3、FUND-04 验收口径；与技术文档 05 既有裁定一致，技术侧零返工。
- **重评条件：**院方制度明确允许特批透支且财务对账口径同步定义。

### 2.2 D-14 一期试点项目类型＝纵向项目

- **结论：**一期以纵向项目为试点类型，配套产出 §16.1 字段清单、附件清单与审批模板。
- **理由：**纵向项目审批链最完整（形式审查＋评审＋多级审批），预算科目模板最标准，最能验证系统主线。
- **否决的备选：**横向（走登记入口，验证不了审批主线与占用控制）、院级（对外部代表性弱）、保持待定（继续阻塞配套材料产出，评审警告 #3 不消除）。
- **遗留：**试点**部门**由院方在阶段 0 指定（建议申报量大、流程稳定的部门），见 §3。

### 2.3 D-15 SSO 协议锁定 OIDC

- **结论：**统一认证按 OIDC 实施锁定；LDAP/AD 仅作组织数据同步补充，本地账号仅受控备用。
- **理由：**技术文档配置示例与 C4 架构图已按 OIDC 编写，标准化程度高。
- **重评条件：**院方现有身份平台仅支持 CAS/LDAP 时（06 文档 R-04 同步关闭）。

### 2.4 D-16 P1 按裁剪准则自动降级

- **结论：**P1 默认一期实施；命中任一条件才降级——①外部依赖未就绪；②试点项目类型不涉及；③经评审会裁决的一期容量/工期冲突（须记录裁决理由）。降级须有降级方案并回写 PRD。
- **当前适用：**仅 FUND-10 因条件②降级（试点类型＝纵向，横向到账/回款特性不涉及）；其余 P1（PORT-05、APPLY-07、RES-07、EXEC-07、CHG-05）按一期实施，技术文档需回补设计（09 文档）。
- **背景：**原表述"一期应尽量完成"不可判定（评审警告 #5），技术整改曾单方降级 P1，裁量权收归需求侧。

### 2.5 D-17 申报状态机补全"不予受理/已关闭"终态

- **结论：**申报单终态集＝{已批准, 不批准, 不予受理, 已关闭}；"已撤回"改为版本级结果标记，撤回后单据驻留草稿态。
- **背景：**APPLY-03（不予受理）、APPLY-08（超期关闭）此前在 §7.1 无状态落点，技术文档被迫自造 NOT_ACCEPTED/CLOSED 且引发命名分歧（评审警告 #1）。技术侧需按本结论对齐状态命名。
