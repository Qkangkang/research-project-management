## 4. 与后端接口对接约定

### 4.1 API 基础地址

| 环境 | 地址 | 说明 |
|------|------|------|
| **开发** | `http://localhost:8080/api/v1` | Vite 代理到后端 8080 端口 |
| **生产** | `/api/v1` | Nginx 反向代理 |

### 4.2 统一响应格式

```typescript
interface ApiResponse<T = any> {
  code: string              // "OK" 表示成功，其他为错误码
  message?: string          // 提示信息
  data: T                   // 响应数据
  trace_id: string          // 追踪 ID
  timestamp?: string        // 时间戳
}
```

**成功示例**：

```json
{
  "code": "OK",
  "message": "success",
  "data": {
    "id": "abc-123",
    "name": "项目名称"
  },
  "trace_id": "4f6c2f0e9a7b4d1c",
  "timestamp": "2026-11-17T10:00:00+08:00"
}
```

**失败示例**：

```json
{
  "code": "RPM-FUND-001",
  "message": "可用余额不足",
  "data": null,
  "trace_id": "4f6c2f0e9a7b4d1c"
}
```

### 4.3 分页参数与响应

**请求参数**（与后端 `page`/`size` 命名对齐）：

```typescript
interface PageQuery {
  page: number              // 页码，从 1 开始
  size: number              // 每页条数，默认 20，最大 200（后端字段名为 size）
  sortBy?: string           // 排序字段
  sortOrder?: 'asc' | 'desc' // 排序方向
}
```

**响应格式**（与后端 `PageVO<T>` 对齐）：

```typescript
interface PageVO<T> {
  items: T[]               // 数据数组
  total: number            // 总条数
  page: number             // 当前页码
  size: number             // 每页条数（后端字段名为 size，不是 pageSize）
}
```

> ⚠️ **重要**：后端 `PageVO` 分页字段为 `size`，不是 `pageSize`。前端调用和绑定时统一使用 `size`。

### 4.4 日期时间格式

- **日期**：`YYYY-MM-DD`（如 `2026-11-17`）
- **日期时间**：ISO 8601 带时区（如 `2026-11-17T10:00:00+08:00`）
- **时区**：统一使用 `Asia/Shanghai`（东八区）

前端使用 Day.js 处理日期：

```typescript
import dayjs from 'dayjs'

// 格式化显示
dayjs(isoString).format('YYYY-MM-DD HH:mm:ss')

// 发送给后端
dayjs(date).format('YYYY-MM-DD')
```

### 4.5 金额格式

- **传输格式**：JSON number，最多 2 位小数（如 `12000.00`）
- **显示格式**：千分位分隔，保留 2 位小数（如 `12,000.00`）
- **货币单位**：人民币元（¥）

前端使用工具函数格式化：

```typescript
// utils/number.ts
export function formatMoney(value: number | string): string {
  const num = typeof value === 'string' ? parseFloat(value) : value
  return num.toLocaleString('zh-CN', {
    minimumFractionDigits: 2,
    maximumFractionDigits: 2
  })
}

// 使用示例
formatMoney(12000) // "12,000.00"
```

| 模块 | 前缀 | 示例 |

### 4.7 认证方式

> ⚠️ **重要**：后端 IAM 模块（rpm-iam）**没有独立的 HTTP Controller**，不提供 `/auth/login` 等登录端点。认证由**院方统一身份系统**（SSO/CAS/LDAP）完成，后端通过 `AuthContextHolder.require()` 从请求头/Session 中解析已认证的 `AuthContext`。

前端的责任：
- 通过院方统一身份入口完成登录，获取 Token
- 后续请求统一携带 `Authorization: Bearer {token}` 请求头
- Token 失效（后端返回 `RPM-COMMON-401`）时跳转到院方 SSO 登录页

```typescript
// api/base.ts 请求拦截器
instance.interceptors.request.use(config => {
  const token = getToken()
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  // TraceID（前端生成，后端通过 MDC 传递）
  if (!config.headers['X-Trace-Id']) {
    config.headers['X-Trace-Id'] = generateTraceId()
  }
  return config
})
```

- **幂等键请求头**：`Idempotency-Key: {UUID}`（关键写操作必须携带，格式为 UUID）
```

### 5.3 路由守卫规则

```typescript
// router/guards.ts
export function setupRouterGuards(router: Router) {
  router.beforeEach(async (to, from, next) => {
    const userStore = useUserStore()
    
    // 1. 设置页面标题
    document.title = to.meta.title 
      ? `${to.meta.title} - 科研项目管理系统` 
      : '科研项目管理系统'
    
    // 2. 匿名路由直接放行
    if (to.meta.anonymous) {
      next()
      return
    }
    
    // 3. 未登录跳转登录页
    if (!userStore.isLoggedIn) {
      next({ 
        path: '/login', 
        query: { redirect: to.fullPath } 
      })
      return
    }
    
    // 4. 首次加载时获取用户信息和权限
    if (!userStore.userInfo) {
      try {
        await userStore.fetchUserInfo()
      } catch (error) {
        ElMessage.error('获取用户信息失败')
        await userStore.logout()
        next({ path: '/login', query: { redirect: to.fullPath } })
        return
      }
    }
    
    // 5. 权限校验
    const requiredPermission = to.meta.permission as string | undefined
    if (requiredPermission && !userStore.hasPermission(requiredPermission)) {
      ElMessage.warning('权限不足')
      next({ path: '/403' })
      return
    }
    
    next()
  })
  
  router.afterEach(() => {
    // 可以在此记录访问日志、上报埋点等
  })
}
```

**守卫职责**：

- ✅ 设置页面标题
- ✅ 未登录拦截（匿名路由除外）
- ✅ 获取用户信息与权限
- ✅ 路由级权限校验
- ✅ 权限不足跳转 403
- ❌ 不处理数据范围权限（由后端控制）

## 6. 权限控制方案

### 6.1 权限模型

```typescript
// api/iam.ts
export interface Permission {
  code: string              // 权限码，如 project:view
  name: string              // 权限名称
  type: 'MENU' | 'BUTTON' | 'API' // 权限类型
}

export interface UserInfo {
  id: string
  username: string
  realName: string
  email?: string
  roles: string[]           // 角色列表
  permissions: Permission[] // 权限列表
}
```

### 6.2 路由级权限

在路由 `meta` 中定义 `permission` 字段：

```typescript
{
  path: '/projects',
  meta: {
    title: '项目列表',
    permission: 'project:view'  // 需要的权限码
  }
}
```

路由守卫在导航前校验，无权限跳转 403。

### 6.3 按钮级权限

**方式一：使用 `v-permission` 指令**

```vue
<template>
  <el-button v-permission="'project:create'">
    创建项目
  </el-button>
</template>
```

指令实现：

```typescript
// directives/permission.ts
import { Directive } from 'vue'
import { useUserStore } from '@/stores/user'

export const permission: Directive = {
  mounted(el, binding) {
    const userStore = useUserStore()
    const requiredPermission = binding.value
    
    if (!userStore.hasPermission(requiredPermission)) {
      el.parentNode?.removeChild(el)
    }
  }
}
```

**方式二：使用 `hasPermission()` 方法**

```vue
<template>
  <el-button v-if="hasPermission('project:create')">
    创建项目
  </el-button>
</template>

<script setup lang="ts">
import { usePermission } from '@/composables/usePermission'

const { hasPermission } = usePermission()
</script>
```

### 6.4 数据权限

**前端不做数据范围判断**，全部由后端接口控制：

- 列表接口根据用户身份返回可见数据
- 详情接口校验用户是否有权查看该资源
- 前端不缓存、不猜测数据权限

**前端职责**：

- 展示 403 错误页面
- 显示"无权限"提示，不泄露资源细节

### 6.5 字段权限（脱敏）

敏感字段由后端脱敏后返回，前端直接显示：

```typescript
// 后端返回已脱敏的数据
{
  "bankAccount": "6222****0202",  // 银行账号只显示后 4 位
  "idCard": "3***************1X", // 身份证只显示首尾
  "phone": "138****5678"          // 手机号中间 4 位掩码
}
```

前端不做二次脱敏，避免与后端不一致。

## 7. 状态管理规范（Pinia）

### 7.1 Store 设计原则

| 场景 | 使用 Pinia Store | 使用组件 `ref`/`reactive` |
|------|----------------|-------------------------|
| 跨页面/组件共享 | ✅ | ❌ |
| 持久化需求（如 Token） | ✅ | ❌ |
| 页面临时状态 | ❌ | ✅ |
| 表单输入 | ❌ | ✅ |
| 列表筛选条件（仅当前页） | ❌ | ✅ |
| 用户信息、权限 | ✅ | ❌ |
| 字典缓存 | ✅ | ❌ |
| 当前工作区项目 | ✅ | ❌ |
| 待办数量（全局） | ✅ | ❌ |

### 7.2 核心 Store 清单

| Store | 文件 | 职责 |
|-------|------|------|
| **用户 Store** | `stores/user.ts` | 登录、登出、用户信息、权限列表、权限判断 |
| **应用 Store** | `stores/app.ts` | 菜单折叠、面包屑、标签页、主题 |
| **字典 Store** | `stores/dict.ts` | 字典数据缓存、查询、刷新 |
| **工作区 Store** | `stores/workspace.ts` | 当前项目、草稿列表、最近访问 |

### 7.3 用户 Store 示例

```typescript
// stores/user.ts
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import type { UserInfo, Permission } from '@/api/iam'
import { iamApi } from '@/api/iam'
import { getToken, setToken, removeToken } from '@/utils/auth'

export const useUserStore = defineStore('user', () => {
  // 状态
  const token = ref<string>(getToken() || '')
  const userInfo = ref<UserInfo | null>(null)
  const permissions = ref<Permission[]>([])
  
  // 计算属性
  const isLoggedIn = computed(() => !!token.value)
  const userId = computed(() => userInfo.value?.id || '')
  const username = computed(() => userInfo.value?.username || '')
  const roles = computed(() => userInfo.value?.roles || [])
  
  // 权限判断
  const hasPermission = (code: string): boolean => {
    return permissions.value.some(p => p.code === code)
  }
  
  const hasAnyPermission = (...codes: string[]): boolean => {
    return codes.some(code => hasPermission(code))
  }
  
  const hasAllPermissions = (...codes: string[]): boolean => {
    return codes.every(code => hasPermission(code))
  }
  
  // 登录
  const login = async (loginData: LoginCmd) => {
    const res = await iamApi.login(loginData)
    token.value = res.token
    setToken(res.token)
    await fetchUserInfo()
  }
  
  // 获取用户信息
  const fetchUserInfo = async () => {
    const info = await iamApi.getUserInfo()
    userInfo.value = info
    permissions.value = info.permissions
  }
  
  // 登出
  const logout = async () => {
    try {
      await iamApi.logout()
    } finally {
      token.value = ''
      userInfo.value = null
      permissions.value = []
      removeToken()
    }
  }
  
  return {
    token,
    userInfo,
    permissions,
    isLoggedIn,
    userId,
    username,
    roles,
    hasPermission,
    hasAnyPermission,
    hasAllPermissions,
    login,
    fetchUserInfo,
    logout
  }
})
```

## 8. 错误处理与交互反馈

### 8.1 四层错误处理

| 层级 | 负责内容 | 实现位置 |
|------|---------|---------|
| **HTTP 层** | 401/403/404/500 统一处理 | `api/base.ts` 响应拦截器 |
| **API 层** | 业务错误码转换、特殊错误 | 各 `api/*.ts` catch 块 |
| **页面层** | 操作反馈、局部降级 | 组件 `try-catch` + ElMessage |
| **全局层** | 未捕获错误、上报 | `app.config.errorHandler` |

### 8.2 统一错误处理示例

```typescript
// api/base.ts 响应拦截器
instance.interceptors.response.use(
  (response: AxiosResponse<ApiResponse>) => {
    const res = response.data
    
    // 业务成功
    if (res.code === 'OK') {
      return res.data
    }
    
    // 业务失败
    handleBusinessError(res.code, res.message)
    return Promise.reject(new Error(res.message || 'Business Error'))
  },
  (error: AxiosError<ApiResponse>) => {
    // HTTP 错误
    if (error.response) {
      const { status, data } = error.response
      
      switch (status) {
        case 401:
          handleUnauthorized()
          break
        case 403:
          ElMessage.error('权限不足')
          break
        case 404:
          ElMessage.error('请求的资源不存在')
          break
        case 500:
          ElMessage.error(data?.message || '服务器错误')
          break
        default:
          ElMessage.error(data?.message || `请求失败 (${status})`)
      }
    } else if (error.request) {
      ElMessage.error('网络错误，请检查网络连接')
    } else {
      ElMessage.error('请求配置错误')
    }
    
    return Promise.reject(error)
  }
)
```

### 8.3 页面层错误处理示例

```typescript
const handleSubmit = async () => {
  loading.value = true
  try {
    await projectApi.create(formData)
    ElMessage.success('创建成功')
    router.push('/projects')
  } catch (error) {
    // HTTP/业务错误已被拦截器处理
    // 这里只处理页面特有逻辑
    console.error('创建项目失败', error)
  } finally {
    loading.value = false
  }
}
```

| 提交失败 | `ElMessage.error` | "保存失败：xxx" |
| 警告提示 | `ElMessage.warning` | "该操作不可逆" |
| 普通提示 | `ElMessage.info` | "数据加载中" |
