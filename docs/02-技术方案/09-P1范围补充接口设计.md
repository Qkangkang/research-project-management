> 需求基线：PRD V2.1（2026-11-17）。D-16 裁剪准则确立后，`PORT-05`、`APPLY-07`、`EXEC-07`、`RES-07`、`CHG-05` 五项 P1 纳入一期（原评审 #28 降级处置废止，见 08 §14.2 修订）。`FUND-10` 按 D-16 条件②降级二期，本文不覆盖。

## 2. PORT-05 外部消息平台链接与免登跳转

### 2.1 接口

| 方法 | 路径 | 用途 | 权限 |
|---|---|---|---|
| POST | `/portal/external-links` | 为本人可访问的资源签发跳转链接（≤5 分钟有效） | 登录用户（目标须通过统一授权服务校验） |
| GET | `/portal/external-links/resolve?token={token}` | 解析跳转：校验→定位→302 目标页或 SSO 登录页 | 归属用户（token 归属校验 + 目标资源二次授权） |
| DELETE | `/portal/external-links/{grantId}` | 撤销未消费的链接 | 授权人本人 |

### 2.2 流程与要点

- **签发**：请求体 `{resourceType: PROJECT|APPLICATION|TODO|REPORT, resourceId, purpose?, channel?}`；校验当前用户对目标资源的常规授权（同一授权服务），通过后生成随机 token，仅存 SHA-256 哈希；`expires_at ≤ now()+5min`（DB CHECK 兜底）。响应 `{url, expiresAt}`。url 形如 `/portal/external-links/resolve?token=...`，不含资源 ID，不可猜测。
- **解析**：哈希比对 token → 存在、未过期、未消费、未撤销 → 若会话用户 = grant.user：标记 `consumed_at`（一次性），302 至目标页；未登录：302 至 SSO 登录并携带 returnUrl，登录后自动重放 resolve（受控登录跳转，满足 PRD"免登或受控登录"）。
- **失败提示**：任何失败（无效/过期/已消费/已撤销/无权）统一返回 `RPM-PORT-001` 或 `RPM-PORT-002` 通用文案，**不返回资源是否存在、名称或摘要**（PRD PORT-05 验收口径；解析成功后仍按目标资源做常规授权复核，无权时同样不给摘要）。
- **防刷**：`(user_id, resource_type, resource_id)` 未消费授权唯一（V07 部分唯一索引）；过期行由 `LinkGrantCleanupJob`（06 §3 任务清单新增第 12 项）每日清理，保留 90 天审计。
- **幂等/并发**：resolve 并发消费以 `consumed_at` 单次 UPDATE ... WHERE consumed_at IS NULL 抢占，仅一方成功。
- **审计**：`EXTERNAL_LINK_ISSUED`、`EXTERNAL_LINK_RESOLVED`（含 IP）、`EXTERNAL_LINK_REJECTED`（不含失败原因细节，仅记录归类）。

### 2.3 验证用例（定义于 §7）

TC-EXT-001～007。

## 3. APPLY-07 专家评审（分配、回避、评分、汇总）

### 3.1 接口

| 方法 | 路径 | 用途 | 权限 |
|---|---|---|---|
| POST | `/applications/{applicationId}/expert-assignments` | 向批次内指定版本分配专家 | `apply:expert:assign`（科研管理） |
| GET | `/applications/{applicationId}/expert-assignments` | 分配列表（专家身份对申请人脱敏为"专家 01"式编号） | `apply:expert:assign`；申请人 403（单盲） |
| DELETE | `/expert-assignments/{assignmentId}` | 管理员移除专家（必填理由） | `apply:expert:assign` |
| POST | `/expert-assignments/{assignmentId}/coi-declaration` | 专家提交回避声明（有冲突：声明 relationType；无冲突：确认） | 专家本人（assignment 归属） |
| POST | `/coi-declarations/{declarationId}/review` | 科研管理处理声明：EXEMPTED（移除）/ CLOSED（确认无冲突继续） | `apply:coi:review` |
| GET | `/applications/{versionId}/review-materials` | 专家查看授权版本材料（评审窗口内） | 专家本人且 assignment=ACTIVE |
| POST | `/expert-assignments/{assignmentId}/submission` | 提交评分与意见（一次，append-only） | 专家本人且 assignment=ACTIVE |
| POST | `/applications/{versionId}/expert-summary` | 生成汇总（规则固定 + 版本留痕） | `apply:expert:assign` |
| GET | `/applications/{versionId}/expert-summary` | 查看汇总：科研管理全量；申请人仅统计口径（不含专家身份与个体意见） | 项目身份/科研管理 |

### 3.2 状态与规则

- **分配**：仅批次内最新提交版本；同一 `(版本, 专家)` 仅一条有效分配（V07 部分唯一约束）；`REMOVED` 后可重新分配，旧行留痕。分配后写入 `todo_item` 通知专家。
- **回避**：复用 `coi_declaration`（`biz_type='EXPERT_REVIEW'`，`biz_id=assignment_id`，relation_type 枚举沿用 DEPT/COLLABORATION/FAMILY/FINANCIAL/OTHER）。未完成声明（无 DECLARED/CONFIRMED 记录）不得提交评分（`RPM-APPLY-006`）；已声明冲突且未被科研管理确认继续（CLOSED）的专家提交被拒（同码，原因字段区分）；管理员移除对应 `EXEMPTED` 处置 + assignment 置 `REMOVED`。
- **评分**：`score_items` 数组由项目类型评分模板校验（项齐全、0～100、权重合计）；服务端按模板重算 total 并比对，不符 `RPM-APPLY-007`；一次提交不可修改（DB 触发器 append-only，对齐"意见留痕"）；提交后 assignment 置 `COMPLETED`。
- **意见隔离**：submission 仅本人与科研管理可读；专家互不可见（PRD §5.2 专家间意见隔离）。
- **材料可见性**：`review-materials` 仅返回 assignment=ACTIVE 且未超 `review_deadline` 的版本材料；下载走 08 §4 鉴权流；专家不可见其他批次/版本。
- **汇总规则（固定，rule_version=`AVG-TRIM-1`）**：有效提交（ACTIVE→COMPLETED 且无未豁免冲突）≥3 方可生成（否则 `RPM-APPLY-008`）；n≥5 去最高最低后算术平均，n∈[3,5) 全体平均；detail 记录匿名编号（专家 01…）各分数与剔除记录；summary append-only（触发器），最新一条为当前结果；生成事件写审计 `EXPERT_SUMMARY_GENERATED`。
- **与立项审批衔接**：汇总生成后可发起/继续 DECISION 阶段审批（`application_review.review_stage='DECISION'`），Flowable 仅编排（D-05 边界）；汇总作为决策附件引用，不自动产生审批结论。
- **脱敏**：`expert-assignments` 列表与 summary detail 对申请人隐藏专家姓名/账号（字段级权限，03 §字段脱敏）；申请人仅见"专家 n 人、平均分、建议分布"。

### 3.3 幂等与并发

- 分配幂等键 `(application_version_id, expert_id)`（唯一约束兜底）；submission 以 assignment_id 唯一约束兜底（重复提交返回原结果 `RPM-APPLY-004`）；summary 生成并发以行锁 + append 顺序为准，重放返回最新汇总。

### 3.4 审计事件

`EXPERT_ASSIGNED`、`EXPERT_REMOVED`（含理由）、`EXPERT_COI_DECLARED`、`EXPERT_COI_REVIEWED`、`EXPERT_REVIEW_SUBMITTED`（不含评分正文，仅 ID 与时间）、`EXPERT_SUMMARY_GENERATED`。

### 3.5 验证用例

TC-RVW-001～012（§7）。

## 4. EXEC-07 轻量任务分派

### 4.1 接口

| 方法 | 路径 | 用途 | 权限 |
|---|---|---|---|
| POST | `/projects/{projectId}/tasks` | 创建并分派任务（可关联交付物） | PI 或被授权成员（`exec:task:assign` + 项目身份） |
| GET | `/projects/{projectId}/tasks` | 项目任务列表 | 项目身份（数据范围过滤） |
| GET | `/users/me/tasks` | 我的任务（含待办聚合进 PORT-01 工作台） | 登录用户 |
| POST | `/tasks/{taskId}/start` | 开始任务 | assignee 或 PI |
| POST | `/tasks/{taskId}/complete` | 完成任务（请求体可携 `deliverableId`） | assignee 或 PI |
| POST | `/tasks/{taskId}/cancel` | 取消任务（必填理由） | PI |

### 4.2 规则

- **无依赖图**：任务为扁平列表，不提供任务间依赖、工时与资源排程（PRD EXEC-07 口径；WBS 维持 §3.3 不做）。
- **显式状态迁移**：领域方法 `Task.start()/complete()/cancel()`（对齐项目规则第 5 条，禁 setStatus 裸改）；迁移图：`TODO→IN_PROGRESS→DONE`；`TODO|IN_PROGRESS→CANCELLED`；`DONE` 不可逆（更正以新建任务替代）；非法迁移 `RPM-EXEC-006`。
- **授权边界**：仅 assignee 与 PI 可 start/complete（成员只能更新授权任务）；cancel 仅 PI；assignee 校验按人员 ID（按账号名判断禁止）。
- **交付物关联**：`deliverableId` 必须属于同一项目且状态 ACTIVE，否则 `RPM-EXEC-004`；complete 时写入 `completed_at`。
- **并发**：version 乐观锁；两人同时 complete 后者收 `RPM-COMMON-409`。
- **通知/待办**：创建与分派写 `todo_item` + `notification`（复用 08 §5 通道）；完成/取消通知 PI。
- **审计**：`TASK_CREATED`、`TASK_STARTED`、`TASK_COMPLETED`（含交付物）、`TASK_CANCELLED`（含理由）。

### 4.3 验证用例

TC-TSK-001～007（§7）。

## 5. RES-07 全院成果库检索与基础统计

### 5.1 接口

| 方法 | 路径 | 用途 | 权限 |
|---|---|---|---|
| GET | `/outputs/library/search` | 全院成果检索（q、outputType、deptId、year、page、size） | `output:library:view`（默认全院用户，可配置收敛） |
| GET | `/outputs/library/stats` | 按 type/year/dept 分组统计（成果去重数） | 同上 |
| GET | `/outputs/{outputId}/library-detail` | 库内详情（脱敏元数据） | 同上 |

### 5.2 规则

- **可见性隔离**：公共库仅含 `status='APPROVED'` 成果；DRAFT/SUBMITTED/RETURNED/REVOKED 不进检索与统计（未公开成果隔离）；`REVOKED` 仅审计可查。部门范围收敛配置生效时按 dept 过滤。
- **敏感附件**：库内详情仅元数据（标题、类型、DOI/专利号、完成时间、关联项目数）；`output_evidence` 不在详情返回，下载走成果原有字段权限 + 08 §4 文件鉴权（附件密级不变式维持）。
- **检索实现**：q 走 V01 既有 pg_trgm 索引（title/doi/patent_no）；`size` 默认 20、上限 100（超限 `RPM-RPT-001` 语义复用：条件过宽）；结果按相关性/更新时间排序。
- **统计口径**：成果去重数（按成果 ID）；不输出"项目关联数"混淆口径（如需按项目统计走 RPT-04）。
- **大数据导出**：不新建通道，复用 RPT-05 授权导出（记录导出人/条件/有效期）。
- **审计**：检索与统计为只读查询不逐次记日志；导出走导出日志（BR-34）。

### 5.3 验证用例

TC-OSR-001～006（§7）。

## 6. CHG-05 重大目标变化重新确定验收标准

### 6.1 接口

| 方法 | 路径 | 用途 | 权限 |
|---|---|---|---|
| POST | `/change-requests/{changeRequestId}/criteria-revision` | GOAL 变更批准生效后创建重定任务（变更生效事件亦自动触发，二者幂等） | `chg:criteria:manage`（科研管理）/系统事件 |
| GET | `/projects/{projectId}/criteria-revisions` | 重定任务列表 | 项目身份 + 科研管理 |
| POST | `/criteria-revisions/{revisionId}/confirm` | 确认新验收标准（写入 revised_criteria，完成重定） | `chg:criteria:manage` |
| POST | `/criteria-revisions/{revisionId}/cancel` | 取消（变更被退回/撤回时） | `chg:criteria:manage` |

### 6.2 规则

- **触发**：`change_request.change_type='GOAL'` 且状态 `APPROVED` 并到达生效日期 → 创建 PENDING 任务；`original_criteria` 为变更前生效验收标准快照（不可变）；幂等兜底：一项目至多一条 PENDING（V07 部分唯一索引），重复触发返回原任务。
- **确认**：科研管理填写 `revised_criteria` 后 confirm；记录 `confirmed_by/confirmed_at`；原始目标保留于 original_criteria + 项目基线历史 + change_request_version（PRD"保留原始目标供审计"三重不变式）。
- **验收联动**：ACC-01 验收条件检查发现 PENDING 重定任务时阻止发起验收（`RPM-ACC-008`），提示先完成标准重定；确认后验收引用最新已生效标准，同时保留原始标准引用（ACC-05 整改与历史意见不变式不受影响）。
- **状态迁移**：`PENDING→CONFIRMED|CANCELLED` 显式方法 `CriteriaRevision.confirm()/cancel()`；CANCELLED 后同项目可因再次 GOAL 变更新建。
- **审计**：`CRITERIA_REVISION_CREATED`、`CRITERIA_REVISION_CONFIRMED`（含新旧标准摘要哈希）、`CRITERIA_REVISION_CANCELLED`。

### 6.3 验证用例

TC-ACR-001～006（§7）。
