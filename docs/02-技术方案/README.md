## 3. 关键设计裁定

| 编号 | 裁定 | 理由/后果 |
|---|---|---|
| D-01 | 模块化单体，一个 Spring Boot 应用和一个 PostgreSQL 主库 | 一期规模与团队复杂度匹配；模块边界由 Maven module 和 ArchUnit 守护 |
| D-02 | 金额统一 `numeric(18,2)`，Java 使用 `BigDecimal` | 禁止浮点；数据库约束兜底金额不为负 |
| D-03 | `fund_event` 只追加不可变，`budget_balance` 是可重建投影 | 支持重放、审计和并发控制 |
| D-04 | `RESERVE/RELEASE/APPROVE/CANCEL/PAY/REVERSE` 成对补偿且幂等 | 支付以财务事实为准；重复回调不重复记账 |
| D-05 | 项目、审批任务、支付/支出、验收状态机相互独立 | 业务状态由业务模块掌握，Flowable 只负责审批编排 |
| D-06 | 申报版本、预算版本、审批模板版本、验收快照不可覆盖 | 历史审批、报表和验收可还原 |
| D-07 | 验收通过生成 SHA-256 归档清单并冻结项目 | 结题后更正走追加式档案更正流程 |
| D-08 | 一期使用 PostgreSQL 事务内 Outbox，不引入 MQ | 避免业务提交成功但事件丢失；后台任务负责重试与补偿 |
| D-09 | 所有列表、详情、附件、导出、异步任务共用同一授权服务 | 禁止前端隐藏按钮式权限；数据范围与字段脱敏一致 |
| D-10 | 外部 HTTP 不进入数据库事务；失败显示同步状态并可重放 | 避免长事务和跨系统强实时耦合 |
| D-11 | 固定报表先于自助分析；一期不做通用 BI | 避免在指标口径未稳定前引入数据权限和性能风险 |
| D-12 | 文件下载使用后端鉴权或不超过 5 分钟的短期签名 | 禁止可猜测 URL；撤销权限后旧地址及时失效 |

## 4. 数据库基线

- DDL：`../../../3-数据库/research-project-management/v1.0/` 下 `V01`～`V07` 七个 Flyway 脚本（清单见 06 §7.2，V07 见 09 §8）。
- 规模：V01 基线 74 张表、80 个索引；V02 新增 4 个物化视图；V03 新增独立 flowable schema；V04～V06 为评审修复迁移（新增 `acceptance_waiver`、`milestone_delay_request`、`expense_special_approval`、`file_upload_session`、`file_download_grant`、`archive_correction_request` 等表）；V07 为 P1 补充迁移（新增 `expert_review_assignment`、`expert_review_submission`、`expert_review_summary`、`external_link_grant`、`project_task`、`acceptance_criteria_revision` 6 表，见 09 §8）。
- 不可变保障：资金事件和审计日志只追加；申报版本、项目基线、验收快照内容不可改；验收材料/归档条目只追加（V04 触发器）；归档包接收后不可改删。
- 数据库约束：预算余额非负、资金事件幂等键唯一、版本号唯一、状态枚举 `CHECK`、生效基线部分唯一索引（V04）、活动成员有效期 EXCLUDE 约束（V04，需 `btree_gist`）。
- 待执行验证：V02～V06 需在空库完成 Flyway 全量建库、重复执行幂等、备份恢复演练（上线门禁，见 06 §7.2/§7.5）。
- `pg_trgm`：基线 SQL 保留扩展和 3 个模糊检索索引；院方环境不支持时按 `02` §9 `DB-01` 移除并采用替代检索方案。
